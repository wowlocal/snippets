## Живые результаты

- **16/16 PASS**: 10 concurrent + все 6 send orders Mac/Android/Linux. Во всех случаях одинаковые 5 записей, все три конкурентные версии сохранены.
- **Clock skew PASS в одном прогоне**: дополнительный синтетический writer с HLC +24 часа и старым `updatedAt`; все четыре версии сохранены, 6 записей. Один прогон не исключает документированное расхождение выбора победителя.
- **Crash-after-user-edit PASS на пяти платформах**: gateway декодирует только публичный синтетический fixture и задерживает ACK целевого изменения; независимый GET подтверждает целевой текст на сервере до kill. Все пять процессов завершены и восстановлены в тех же data roots. После трёх циклов обмена одинаковые 3 записи, лишних копий нет.
- **Paging PASS**: snapshot из 128 записей / 3 страницы; затем 125 последовательных версий одной записи. Все пять клиентов сошлись к последней версии и 128 записям без копий. Linux: первый импорт 36.95 с, обработка истории 58.62 с, следующий проход без изменений 2.07 с (VM + HTTPS tunnel, не performance SLA).
- **Старые Linux-журналы PASS, офлайн**: 10 исторических копий, одна с pending outbound packet; чтение, сохранение новым codec и повторное открытие сохранили всю модель journal intent, включая её точные пакеты. Исходники журналов не изменялись. Сетевой replay не проверялся.
- **Native cloud PASS, 15/15 фаз**: account-key authentication, refresh/logout, server CAS, отсутствие тестового plaintext в wire blobs, lost ACK при удалении, truncated page и stale cursor; в конце 2 live + 1 tombstone.
- **Пять клиентов с удалением и Linux Keep**: все тексты и поля сохранены, стабильные 8 записей. Старый oracle ошибочно ожидал 7 и iPhone-текст в original. Это несовместимо с явным Keep как новой правкой. [Разбор ошибки теста](issues/cloud-account-key/07-e2e-keep-oracle.md). Отдельный пятисторонний сценарий без удаления прошёл: 7 одинаковых записей, все 5 текстов, 4 отключённые копии и независимые поля сохранены.

- **Crash-first-batch PASS на пяти платформах**: на iPhone и iPad сервер принял первый пакет без пользовательской правки; процесс убит до ACK. После одного recovery phase целевая правка уже подтверждена независимым GET на сервере. На Mac/Android/Linux первая отправка уже содержала целевой текст. После трёх полных циклов у всех 3 одинаковые записи без конфликтных копий. Это отдельно закрывает ложноположительное допущение прошлого crash-теста.
- **Native UI auth PASS**: iPhone 1/1, iPad 1/1 (0 skipped), Android instrumentation 1/1. Apple: отмена, ошибочный check symbol, создание/сохранение ключа, повторный вход со строчной display form. Android дополнительно проверил неизвестный корректно сформированный ключ, refresh/revoke, Activity recreation и повторный logout.

Санитизированные агрегаты: [evidence/round2](issues/cloud-account-key/evidence/round2/). Исходный failed-результат пятистороннего оркестратора сохранён отдельно от последующей классификации: ошибка проверки не скрыта.

## Ограничения

Смена аккаунта при задержанном ответе не повторялась в новом живом прогоне (результаты первого раунда не выдаются за повторную проверку текущего HEAD). Нативный повторный вход и unit/integration проверки account binding прошли.

Новые перекрёстные approvals с kill между approve/bind/commit и реальным ожиданием 10-минутного expiry не выполнялись; обычный backend auth/device regression suite прошёл.

Физические iPhone/iPad, Production CloudKit, биометрия и холодный старт активного cloud-provider на реальном устройстве в этот раунд не входят. Hyprland в текущей Arch VM повторно остановился с `CBackend::create() failed` до запуска Snippets; Omarchy/PAM и compositor-specific вставка не считаются проверенными. Linux timeout flake из issue 05 остаётся известным: один успешный полный набор не доказывает её устранение.

Между независимыми пакетами fixture очищались только creation-rate counters нового одноразового backend, чтобы ограничение 10 новых аккаунтов/час не подменяло sync-проверки. Production код лимитов не менялся; persistent rate limits проверены отдельным PostgreSQL integration suite.
